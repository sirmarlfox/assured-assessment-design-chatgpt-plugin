## Limits and nearest workarounds

| Difference | Nearest workaround |
| --- | --- |
| A skills-only plugin cannot switch on or guarantee the host session web-search capability. | Use a search-enabled session. If unavailable, disclose this and use the dated baseline registry. |
| Search can fail to retrieve a page or full PDF. | State exactly what could not be retrieved; label snippet-only evidence, use the baseline for that entry and avoid claiming a full read. |
| Model output and reference retrieval are not deterministic across Claude and ChatGPT. | Preserve the complete instructions, require reference lookup, and run the documented live checks. Do not claim identical output on every run. |
| Native plugin metadata supports three launch prompts. | Keep all four requested starters in a separate file; expose the first three in the manifest. |
| Legacy custom GPT editors may impose a smaller instruction limit and new GPT creation is account-dependent. | Use the native plugin, which includes the full instructions. Do not truncate the workflow or treat setup metadata as an importable GPT. |
| Document generation depends on tools available in the session. | Use the session document tool when available; otherwise provide the complete document text and disclose that a downloadable file could not be generated. |

The plugin is not an independent search engine and cannot run Step 0 in the background. No new server, app endpoint or source has been invented.
